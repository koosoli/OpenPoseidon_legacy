# Performance audit, 2026-10-17 (static, code-only)

Branch `MrDudeX-perf`, based on `perf/optimization-20261014` @ `6b0fa15`.

**Status: nothing in this document is measured yet.** It was written in a cloud session
without access to the game PC, by reading the code. Every item is a hypothesis with a stated
exactness argument and a stated measurement; none may be implemented as a "win" before that
measurement exists. It builds on `docs/perf-audit-20261014.md` (the owner's measured audit) and
does not repeat what that audit already did or rejected.

Line numbers refer to `6b0fa15`.

## 1. Threading model as it is today

| Thread | Where | Notes |
|---|---|---|
| Main (T1) | `Core/Game/GameLoop.cpp:363` → `World::Simulate` (`World/World.cpp:265`) | simulation, AI, scripts, scene walk, draw recording, publish |
| `task-pool-N` (enkiTS) | `Core/TaskPool.cpp:95` | `ParallelFor` (blocking, `_submitMutex`), `Submit` (fire-and-forget); ≤16 incl. caller; `--max-threads` |
| `obj-prep-0/1` | `ObjectStreamPrepare.cpp:1942` | object streaming preparation |
| `wgr-render` | `EngineWgpu.cpp:5640` | one command encoder per frame (`rust/src/lib.rs:4836` … `finish()` `:7228`, one submit `:7252`) |
| canopy / sky-vis / init threads | `EngineWgpu.cpp:17569`, `rust/src/terrain/skyvis.rs:225`, `lib.rs:1701/1993/2110` | per job / start-up only |
| audio pump | `SoundSystemOAL.cpp:271`, `SoundSystemSteam.cpp:197` | large waves decode via `pool->Submit` |

**Per frame, neither the simulation nor the draw walk uses the task pool.** Every
`ParallelFor`/`Submit` site is in loading, streaming, texture encoding or audio decode.

The two things that block parallel simulation/draw work, found in the code:
1. **Shared shapes are mutated per object.** `Animate`/`Deanimate` write the vertices of the
   shared LODShape; even line-of-sight tests do it (`Object::Intersect` →
   `AnimateComponentLevel`, `ObjectIntersect.cpp:810`, invalidating convex components,
   `Object.cpp:821`).
2. **One sequential RNG stream** (`GRandGen`, guarded in `randomGen.cpp:23-40`). Any parallel
   stage must keep the draws in the original order.

Main-thread-only constraints: `FileCache` (`FileServer.cpp:48`, see the crash fixed in
`5044760`), `ShapeBank` loading, `FastCAlloc`, `GGameState`, the AI hierarchy, and the whole
`wgr_*` ABI ("one thread at a time"; resource creation waits in `AcquireProducerWindow`,
`EngineWgpu.cpp:5456`, ~60 call sites).

Existing determinism tooling that new parallel code must pass: `World::RecordTickStateHash`
(`World.cpp:2657`), `test_worker_determinism.cpp`, `test_deterministic_commit.cpp`,
`[race]` tests, the `linux-x64-clang-tsan` preset and CI job (`.github/workflows/build.yml:108`).
`tsan-suppressions.txt` suppresses only third-party code.

## 2. Findings

Each finding: location, why it costs, proposed change, why it is exact, risk, effort, what to
measure. Effort S/M/L.

### R1. Pre-baked skinned draws still break instancing (renderer)
- `plan_3d` treats every draw with a palette and a skinned mesh as a barrier:
  `gfx3d/mod.rs:9157` (`skinned = palette_slot != NO_PALETTE && mesh.skin.is_some()`),
  while the other three sites (`:9049`, `:9087`, `:9338`) already exclude baked draws.
- With temporal/DLSS on (default, `lib.rs:1819`), soldiers are compute-skinned and drawn
  through the rigid pipeline anyway. As barriers they become `DrawKind::Direct` count 1 and
  `flush_run` also cuts the surrounding static-object bucket.
- **Change:** a baked, opaque, offset-free TestWrite draw becomes an ordinary bucket entry
  inside the run (`base_vertex` = bake base, whole `skinned_vbuf` bound), submitted with the
  run's `multi_draw_indexed_indirect`.
- **Exact:** same pipeline, same vertices, same per-instance slot; reordering inside an opaque
  run is the assumption `plan_3d` already makes for rigid draws (`mod.rs:9096-9106`). The colour
  and prepass shaders do not read `vertex_index` (only velocity shaders do — to be re-checked).
- **Risk:** coplanar faces under GreaterEqual in the write-off colour pass (same as existing
  bucketing). **Effort:** S–M, Rust only, no ABI change.
- **Measure:** PERF-005 `direct_calls`/`indirect_calls`, render-thread encode time, GPU pass
  timers, pixel diff on/off, on the deterministic free-fly bench (`--test-world-freefly …`,
  `POSEIDON_LOCKSTEP_HZ=30`). This is the cheapest attack on the audit's item 0 (3,767 direct
  ops, render thread ~99 % busy).

### R2. One compute dispatch per soldier and mesh for the skin bake
- `prepare_skin_bake` makes one `BakeGroup` per (palette slot, mesh), `instance_count: 1`
  (`gfx3d/mod.rs:6558-6588`, dispatch `:6736-6767`).
- **Change:** one group table in a storage buffer, one dispatch. Per-vertex math unchanged.
- **Exact:** yes. **Effort:** S–M. **Measure:** dispatch count, bake encode time.

### R3. Shadow-caster loop re-sets all state per bucket
- `gfx3d/mod.rs:8120-8170` sets pipeline, four bind groups, vertex and index buffer per
  bucket, without the `Pass3dState`-style tracking the main pass has. Baked casters are always
  their own count-1 bucket (`:7881-7895`).
- **Change:** track last-set state. **Exact:** redundant set calls do not change results.
  **Effort:** S. **Measure:** cascade encode time.

### R4. Rigid direct draws slice the vertex buffer per mesh
- `draw_one` binds a slice per mesh (`mod.rs:9456-9468`), i.e. one `set_vertex_buffer` per
  draw. Binding the whole pool buffer and using `base_vertex` avoids it.
- **Exact:** only where no slot-1 skin buffer is bound (exclude the `WGR_SKIN_BAKE=0` VS
  fallback) and the shader does not read `vertex_index`. **Effort:** S.

### R5. Parallel command recording (render thread)
- Single encoder per frame. `Renderer`/`Gfx3d` are `!Sync` because of `Cell` fields
  (`lib.rs:932-941`, `gfx3d/mod.rs:4521-4656`).
- **Change:** record shadow cascades and the object pass on separate encoders on worker
  threads, submit in today's order. Requires converting the `Cell` statistics to atomics or
  thread-local counters.
- **Exact:** submit order unchanged. **Risk:** medium (borrow structure, bindless registry).
  **Effort:** M–L. Do R1–R4 first; they cut the command count itself.

### R6. Receiver-aware shadow cascade cull
- Already proposed in the 10-14 audit (1–2 ms estimate). Location: `gfx3d/cull.rs:4198`
  (`params_from_shadow_cascade`), `cull.wgsl:146`, cache in `EngineWgpu.cpp:18572`.
- The receiver region must be the union over every consumer that samples shadows outside the
  view: blend band of the previous tier, `csm_occlusion_point`, `godrays.wgsl`, the underwater
  froxel volume, optics/cockpit segments with their own camera, the planar reflection camera.
  The cascade cache must store the receiver planes it was rendered with.
- **Risk:** missing one consumer = wrong shadows. **Effort:** M–L. Needs a debug switch and a
  pixel diff covering water reflection, optics and god rays.

### S1. Arma 2 C0: vehicle simulation 9 → 600–700 ms per tick after ~10 s
Measured by the Arma 2 session, not reproduced here. Ranked hypotheses from the code:
1. **Contact damage on shared proxy objects.** `Car.cpp:1146` (and `Motorcycle.cpp:934`) call
   `obj->LocalDammage(...)` on whatever `Object::Intersect` reports, without filtering
   `hierLevel`; Intersect reports *proxies* of the hit model (`ObjectIntersect.cpp:632-653`).
   Tank (`Tank.cpp`) and soldiers filter `hierLevel`. Proxies created for Arma ODOL models are
   `Temporary` (`VehicleTypes.cpp:874-887`) and live in the parent model's shape, so they are
   shared by all instances of that model. Once damaged, `IsAnimated()` is true
   (`Object.cpp:324`) and every later `Intersect` re-animates the geometry and recomputes the
   convex components (`Object.cpp:836-846`, `ObjectIntersect.cpp:566`) — on large Arma 2
   geometry LODs. `LocalDammage` → `DoDammage` → `GetNetworkId()` on such a proxy logs
   **"Type is not primary"** (`Dammage.cpp:226`, `:755-762`), which explains why that count
   varies between runs. This is also a correctness bug: damage on a shared proxy accumulates
   across every instance of the model.
2. Roadway contact without a spatial index (`Collisions.cpp:901-1000`, `517-583`) once the
   LHD's parts are resident (~8 s, `docs/roadmap/ARMA2-ASSETS-20261014.md:67`).
3. Log spam: spdlog flushes every line when a file sink is open (`Logging.cpp:617-637`).
   Side cost unless counts are very large.
4. Fast-vehicle list (1 ms sub-steps) filling up.
5. Footprint/mark build-up (10 s TTL).

One run with `POSEIDON_SIM_VEHICLE_COST=1` plus three small diagnostics separates them:
top-3 entities per second by `Simulate` time with names; first-damage log per object with
`hierLevel` and geometry vertex count; roadway vertex × face counter. Fix candidate for H1:
filter `hierLevel > 0` in `Car`/`Motorcycle` contact damage as `Tank` does — **this changes
behaviour** (proxies no longer take damage), so it needs the owner's decision even if it
removes the slowdown.

### S2. Visibility and target tracking: the pure parts can run on the pool
- `SensorList::SmartUpdateAll`/`UpdateCell` (`Terrain/Visibility.cpp:335-427, 550`): which
  cells update is decided by a dirty test, not by results; the cost is `Landscape::Visible`
  (`Collisions.cpp:2169`).
- `EntityAI::TrackTargets` (`Detection/Target.cpp:885`): `CalcVisibility` reads visibility;
  `GetVisibility` creates rows/columns through a `const_cast` (`Visibility.cpp:620-640`), and
  `posError` draws from `GRandGen` (`:1514`, `:1594`).
- **Change:** select serially (unchanged budget), pre-create sensor rows/columns and pre-animate
  the animated obstacles serially, compute the ray tests with `ParallelFor`, commit results and
  RNG draws serially in the original order.
- **Exact:** if animation and RNG stay serial. **Risk:** medium. **Effort:** M.
- **Measure:** profile share of `Landscape::Visible`/`CheckVisibility`, `AICost` buckets;
  `TickHash` identical with the switch on and off.

### S3. Skinning palettes computed ahead, in parallel
- `Man::Animate` (`SoldierOldSimProxy.cpp:1512`): `PrepareCorrectedPose` is `const` and writes a
  local array; `AnimationRT::PrepareMatrices` lazily loads through `GAnimationRTCache` (main
  thread only, via FileServer); `ApplyMatrices` writes the shared buffer.
- **Change:** preload RTMs serially for visible men, compute the corrected poses on the pool
  into per-object buffers, let `Animate` (pass 1 and shadow pass) consume them. Section hiding
  stays serial (the 10-14 audit showed the shadow pass cannot reuse pass 1's palettes).
- **Exact:** same function, same inputs. **Effort:** M. **Measure:** byte compare of the
  palettes (a `verify` mode like `POSEIDON_BLEND_RECORD=verify`), `Man::Draw` share.

### S4. Shadow-caster filter
- `RenderShadowMapDepthPassGpu` (`SceneShadowPass.cpp:521-560`): the filter (distance,
  `NoShadow`, coverage, LOD) only reads; `AddShadowCaster` animates.
- **Change:** filter with `ParallelFor` into an index list, add casters serially in index
  order. **Exact.** **Effort:** S. Gain probably small.

### V1. Script evaluator re-parses text on every evaluation
- `engine/Evaluator/express.cpp` is a pure text interpreter: `compile` returns the string
  (`GameStateExt.cpp:1369-1375`), `call`, `if/then`, `while`, `forEach` re-parse each time;
  every `{...}` literal allocates a new `RString` per evaluation (`:323-324`).
- Per-tick evaluators: trigger conditions in `Detector::Scan` (`Detector.cpp:1199-1205`),
  waypoint conditions (`AIArcade.cpp:331-333`), user actions (`VehicleAIPilot.cpp:1446`),
  SQS `@` lines and `waitUntil` (`Scripts.cpp:466-489`, `:1533`).
- Identifier lookups: up to three `_vars` lookups per identifier plus a function/nular lookup
  (`express.cpp:1706-1712`, `:213-216`, `:2511-2541`), each allocating an `RString`;
  `MapStringToClass` starts with 15 chains and the `GameState` constructor reserves nothing
  (`HashMap.hpp:18-26, 70, 390-405`; `express.cpp:2399-2456`), so ~1,100 registered names sit
  in ~15 chains of strcmp.
- **Exact cheap steps (S each):** rebuild the function/operator/nular tables with more chains
  after registration (only `ForEach` order changes — check the dictionary export at
  `express.cpp:2386-2396`); look up identifiers from a lower-cased stack buffer; pass the found
  `_vars` entry through `Vyhod` → `Const` → `VarGet`; `VarGetLower` for constant names
  (`_time`, `this`, `thisList`, `_x`, `_this`).
- **Larger (M–L):** a token cache per expression. Exact only if the runtime "a variable of the
  same name shadows a command" checks and the error texts/caret positions stay identical.
- **Not exact, do not do:** throttling trigger scans (`_nextCheck` is set at `Detector.cpp:77`
  but never read — leaving it unread is what keeps today's timing).
- **Measure:** evaluates per frame by caller (`s_traceExpression` hook), sampler share of
  `Vyhod`/`Const`/`VarGet`/`MapStringToClass::Get`/`strcmp` on a trigger-heavy campaign
  mission; `PoseidonEvaluatorTests` unchanged.

### L1. Native `.ent` parse (10-14 audit item 4)
- `std::vector<EbinPlacement>` (`Asset/Formats/Enfusion/EbinWorld.hpp:189`), filled by
  `push_back(placement)` at `EbinWorld.cpp:398` without reserve; ~168 B per element × 1.23 M;
  `kMaxSingleAllocation` 256 MiB (`JimboAllocator.hpp:19`), zeroed by `mi_zalloc_aligned`.
- The push **copies**; the 16-char GUID exceeds the inline string buffer, so up to ~2.4 M extra
  heap allocations.
- **Change:** (S) read the fields back from the vector element and `push_back(std::move(...))`;
  (S) reserve from a measured bytes-per-placement estimate, capped; (M) chunked container.
- **Exact:** same elements, same order. **Measure:** time in `ReadEbin` (~0.8 s today).

### L2. Grass road/footprint table rebuild (10-14 audit item 5)
- Binning is already incremental (`Geography.cpp:997-1033`). Still rebuilt every refresh: the
  flatten over all 1,048,576 cells and a fresh `words` vector (`TerrainWgpuEnfusionClutter.cpp:940`),
  `data.to_vec()`, a new GPU buffer and a forced bind-group rebuild
  (`rust/src/grass/mod.rs:2197, 3488`).
- **Change (M):** keep `words` alive, per-cell capacity blocks, upload dirty ranges with
  `queue.write_buffer` through a new FFI call; full rebuild only when capacity runs out.
- **Exact:** the shader follows (offset, count); per-cell append order and the first-255
  truncation stay. **Measure:** split the 18 ms first (`UploadGrassRoadCells` vs. the rest of
  `UploadGeography`).

### L3. Allocator zero-fill (10-14 audit item 6)
- `JimboAllocator::New` → `mi_zalloc_aligned` (`JimboAllocator.cpp:123`); callers rely on it.
- **Change:** `NewUninitialized` plus a one-shot, size-matched thread-local scope, used only at
  `std::vector(n)`/`resize(n)` sites — the vector value-initialises its elements itself, so
  skipping the allocator's memset there is exact by construction. Candidates:
  `PakArchive.cpp:401, 436` (every `.edds`/`.xob`/`.ent` read), `DdsImport.cpp:157` and its
  decode targets, `TextureWgpu.cpp:1388, 1562, 2077, 2395, 2399, 2711`,
  `TerrainWgpuEnfusionClutter.cpp:1040`. No raw `new T[n]` sites.
- **Risk:** low if the scope stays one-shot and size-matched; no-op under ASan.

### L4. Far-tier `.emat` maps on the main thread (10-14 audit item 3)
- `RegisterGpuModel` (`EngineWgpu.cpp:14908`) loads each `.emat` slot via `_wbank->Load` +
  `EnsureUploaded` (`:13367, 13463, 13667, 13871, 15902, 15970, 15991, 16150, 16193`).
- **Change (M):** extend `PrepareNativeInstallTextures` (`ObjectStreamPrepare.cpp:3139`) with
  the `.emat` slot names from `LoadTranslatedMaterial`, seed `_materialBindings` on the main
  thread, wrap the far `NewFromModel` (`LandSave.cpp:5900`) in `NativeInstallTextureScope`.
- **Exact:** the factory takes a prepared source built with the same options; anything not
  prepared is created as today. **Open:** `LoadTranslatedMaterial` off the main thread
  (`SetEmatGuidPaths`, mount) needs a thread-safety audit. The 10-14 audit rejected a
  *pre-registration* variant (superset of names, fill got slower); this one prepares per
  install batch, the pattern that measured well for face textures.

### L5. FLY-001 texture ingress (`53aa9b3`, opt-in) — before default-on
- Covers the five create sites in `TextureWgpu::EnsureUploaded`. Still window-gated: destroy,
  slot release, `wgr_texture_update`, the two direct `wgr_texture_create_in_slot` sites
  (`TextureWgpu.cpp:1422, 2085`), 18 sites in `TerrainWgpu.cpp`, `EarthTreeDetail`,
  `ProceduralTrees`, `BirdFlocks`.
- **Possible visual regression found:** when the 64-lease pool is empty, `slot_acquire`
  returns 0 and the texture takes an unleased slot at the drain; a later evict/re-upload gets a
  different slot, which breaks REN-RES-001 (registered models bake the bindless index).
  **Fix:** fall back to the window path when the pool is empty, and count it.
- Also: the cached `ingressOwner`/`ingress` statics are keyed on the renderer's address (dangle
  if a renderer is recreated at the same address); ingress handles resolve through a `HashMap`
  on the render thread.
- **Measure:** `lazyWait` (10-14 audit: 9–11 ms per frame during the native fill), `winWait`,
  `g_rendererRuleViolations`, pool misses, render-thread busy; stress eviction under the VRAM
  budget, world switch, resize; pixel A/B.

## 3. Not recommended

- Parallel per-entity simulation (`SimulateOnly`, `WorldSetup.cpp:626-692`) or
  `AICenter::Think`: the list grows during the loop, entities mutate the world, RNG is shared;
  SIM-811 says so explicitly. Needs a commit stage first (architectural).
- Fully retained/instanced skinned soldiers before R1–R4: L effort, high exactness risk
  (per-instance section masks, texture overrides, forced LOD, blend sections), and little main
  thread saved because `Animate` must still run for the palette.
- Throttling trigger scans (V1): changes activation timing.
