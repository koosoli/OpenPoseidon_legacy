# Native Reforger material appearance audit, 28 September 2026

Oliver reported that the native Reforger world looks generally matte and flat. A read-only source and original-asset audit found a concrete material-data gap: `EmatMaterialAdapter.hpp::TranslateEmat` brings BCR/NMO/NTC/Mask and NormalPower into translated material data, but does not carry the authored metalness and roughness scales or layer values through to the object shader. The retained `shading.wgsl` path still uses legacy `spec_power`/Blinn-Phong and coarse SH-9 sky response, while terrain lacks sky specular. This supports a broad material-model mismatch as a hypothesis, not a verified single cause of every dull frame. No shader, import path, or installed binary was changed by this audit.

Read-only original-archive checks found nonconstant BCR alpha on `Granite_05_BCR.edds` (BC7, 1024², observed alpha 101–255, mean 239), `ST_MetalPaint_Coated_02_1m_BCR.edds` (BC7, 1024², alpha 37–119, mean 68.6) and `WaterTank_01_MLOD_BCR.edds` (BC7, 256², alpha 131–255, mean 220.4). The WaterTank material uses `MatPBRBasic`, BCRMap and MetalnessScale 0 without OpacityMap. Bohemia's [Reforger texture naming documentation](https://community.bistudio.com/wiki/Arma_Reforger%3ATextures) describes BCR RGB as colour and its alpha as roughness. The current shader instead treats sampled base alpha as coverage/output, without using it to drive roughness. These three samples support a real data-loss path, not yet an image-quality or whole-corpus parity result.

A naive global BCR-alpha change would be wrong. `LandLoadEnfusion.cpp` builds an `enfa|opacity|colour` composite for alpha materials; `TextureWgpu.cpp` deliberately replaces its base alpha with coverage. On `MatPBRMulti`, `gpu_driven.wgsl` blends RGB for later BCR layers but currently keeps the first layer's alpha, so roughness must follow the same mask weights as colour. NMO metalness/AO packaging also needs an exact decoded-channel check before a PBR shader consumes it. The audited native path has known separate incomplete shader/material and asset/furniture coverage; neither the Reforger map nor one asset is a complete visual oracle.

Next bounded work: add default-off section provenance/debug values for genuine opaque BCR roughness and authored metalness/roughness controls; prove an opaque WaterTank or Granite section and an opacity-composited Alnus leaf section give distinct roughness-versus-coverage origins. Then add a native-only shader route that uses the already fetched BCR alpha with correct multi-layer weights, preserving CWA/DayZ legacy shading and all alpha coverage behavior. Include the direct-draw route or explicitly leave it gated until the matching ABI exists. Compare fixed native poses and GPU pass timings, with one CWA/DayZ regression capture, before enabling by default. No visual or performance acceptance was obtained in this read-only audit.

Source follow-up `de82e553` records original opaque `_BCR.edds` alpha provenance and authored roughness/metalness values in `TranslatedMaterial` only when `WGR_REFORGER_PBR_PROVENANCE=1`. Default translation does not scan the extra scalar keys or allocate the provenance record; its default-null shared pointer adds 16 bytes per translated material. The isolated test build passed `[emat]` in both modes (default-off 319 assertions/43 cases; opt-in 342/43), and the combined five-target build plus paired installed WGPU startup passed. This is CPU source metadata, not a GPU material ABI, shader fix, native scene validation or performance acceptance. The next visual step must establish the exact NMO channel/decode path and gate opaque roughness separately from cutout coverage in both object draw routes.

The follow-up channel audit found the concrete pre-shader blocker. Native `_NMO.edds` carries normal X/Y in R/G, metalness in B and ambient occlusion in A. Compressed BC7 pass-through and decoded ARGB8888 preserve NMO B/A through upload, but `gpu_driven.wgsl` and `shader3d.wgsl` currently use only the normal channels. In contrast, the decoded `_BCR.edds` route in `DdsImport.cpp` overwrites every alpha byte with 255 to force opaque classification; compressed pass-through retains roughness alpha. Thus enabling roughness in WGSL alone would behave differently by texture mode. Preserve BCR data alpha in the decoded route while keeping alpha classification opaque, and leave the `enfa|` opacity composite's alpha as coverage. A native-only first visual slice should be limited to genuine opaque `MatPBRBasic` sections with both original BCR and NMO bound, excluding cutouts, composites, converted PAA, Multi and 2Layers. `MatPBRMulti` additionally lacks a bound `NMO_1` layer and the direct draw path lacks matching layer bindings. A small AO-on-sky step and raw R/M/A debug view can precede a separately validated roughness/metalness BRDF. Both object draw routes and CWA/DayZ fallback, matched frame timings and fixed native poses must pass before a default change. This remains an analysis finding, not an implemented visual fix.

Source `8ec069f4` now retains the authored roughness alpha for genuine native `_BCR.edds` through decoded and lazy-tinted paths. `TextureWgpu::Init` no longer forces a coverage scan for exactly those source names, while `enfa|` remains a separately classified cutout whose alpha comes from OpacityMap. Focused EDDS tests passed 1,318 assertions with one known preparation skip; combined five-target build and paired installed WGPU startup passed on `7084be0a`. One installed native Reforger eight-pose route `native-bcr-sky0-20260928-20260928-101030` passed/normal, returned to 19,999 resident/0 pending and the same 1,707,629,924 tracked GPU bytes as the prior fixed route, with no renderer validation error. This is source-channel preservation and a bounded stability check, not a shader/PBR visual fix or matched FPS proof. Review follow-up `4a85b88a` restores the previous opaque-alpha behavior for legacy lazy-tinted `_BCR.dds` names; its focused BCR test passed 99 assertions/2 cases, and the combined five-target build with `9ab82ed3` passed. Installed verification of that combined build remains pending.
