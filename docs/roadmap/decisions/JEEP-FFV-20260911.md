## Reproducible installed baseline

`scripts/Test-JeepPassenger.ps1` uses `dev-missions/jeep-ffv.Intro` and the
installed game under the shared game lock, with an isolated version-3 graphics
profile. Original Jeep, cargo passenger SoldierWB, M16 only, target to the
right of the vehicle. Installed original Jeep has a windscreen and fabric roof:
the first supported arc must use the open passenger side, not the front glass.

Valid baseline: build/jeep-ffv/baseline-20260911-052435, installed e1738ab4.
Cargo: remains inside, 30 loaded rounds, zero Fired events, target damage zero.
After real ejection: two M16 Fired events, total rifle rounds 60 -> 58,
loaded rounds 30 -> 28, target damage 0.513834. Clean exit, no renderer error.
Screenshots and responses.jsonl retained with the installed stamp.
This confirms the missing cargo path and a working on-foot control, not FFV.

Excluded observations: first fixture allowed shooting before boarding; another
allowed the standard hand grenades, whose damage/Fired events are NOT rifle
acceptance. A subsequent valid rifle run hit a Windows PowerShell JSON-array
enumeration error in the test; the raw responses were correct but the run is
not counted as a clean acceptance. The fixture now removes original magazines,
supplies only two M16 magazines and checks rifle ammunition as well as events.

## Concrete integration points

- TransportCore.cpp Transport::Simulate advances cargo via BasicSimulation,
  not Soldier::AI/AIFire. Do not call the full walking/physics simulation on crew.
- SoldierOldMove.cpp Man::SwitchVehicleAction resolves the existing vehicle
  animation map and resets leg transform. RTM_0101 is supported by the current
  reader; the reference Jeep co-driver animation has 25 named bones, 3 phases
  and zero root motion. Reference extraction stays under build, not in a pack.
- TransportCore.cpp GetProxy and ProxyWorldTransform supply the actual animated
  seat frame, including model bounding-centre adjustment. Entity::WorldTransform
  already resolves hierarchy; do not independently reconstruct the seat origin.
- VehicleAICombat.cpp EntityAI::FireMGun previously used the independent entity
  frame and speed, which are not the seated proxy frame. The first code increment
  uses WorldTransform/WorldSpeed for attached shooters while preserving the
  existing unattached path and random dispersion order. No new bullets, ammo
  rules or duplicate fire callbacks. This does NOT enable passenger shooting.
- Existing WorldSpeed inherits parent translation only. Angular muzzle velocity
  during turns remains an explicit follow-up; do not claim full moving FFV.
- SoldierOldAI.cpp AIFire/FireWeapon already contain target permission, aiming,
  weapon readiness, projectile creation and recoil. Reuse, not duplicate them.
- AIGroupImpl.cpp can order cargo out on combat transition via unloadInCombat.
  Any exemption must be for an explicitly supported active seat only, not all
  cargo, and must not suppress a user's/script's actual disembark order.
