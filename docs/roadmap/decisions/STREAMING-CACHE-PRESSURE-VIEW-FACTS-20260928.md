# Optional cache pressure and private view-reference bookkeeping (28 September 2026)

Commit `e45e677f` adds two bounded, separate streamer slices. `WGR_OBJECT_STREAM_PRESSURE_CACHE_TRIM=1` observes the existing GPU tracked-byte/budget facts and, only after eight consecutive over-budget residency updates, suppresses new redundant last-holder `Shape` cache references and drops at most one oldest cache reference per update. Eight consecutive samples below 85% restore normal caching; unavailable facts reset the policy. The flag is **off by default**. Active scene objects, collision ownership, the memory budget, and GPU pool retirement are unchanged. Dropping a reference is not evidence of physical GPU reclamation and may increase later reload work. The convergence runner exposes the exact opt-in switch and read-only cache/GPU counters.

At `e45e677f`, the new Rust `view_reference_facts` module was a pure, fixed-size 36-view/three-pending-*view* state machine with an 80-byte proposed copied layout. It refused an absent bit without a committed, successful exact-view sample for the current instance epoch and actual pass generation. The follow-up below supersedes this per-view slot design. There is **no GPU COUNT producer, readback, exported getter, consumer, or eviction decision** yet, so this code does not establish safe Fine-page retirement.

### Follow-up `0a063953`: bounded raP source and corrected frame slots

The Rust bookkeeping now holds three **frame** readback slots, each allowing up to 36 copied view COUNT words. Proposed layout v2 is 96 bytes and includes target model, instance handle and source generation. Copied and actually submitted view masks are distinct; an aborted, stale, disabled/re-enabled, same-generation refreshed, missing or failed sample stays Unknown without recycling an in-flight slot. The first v2 compile failed because the bundled Rust toolchain does not derive `Default` for `[u64; 36]`; removing the unused derive repaired it. Nine focused Rust tests passed. This is still unused pure state. Because main/cascade pass generations can advance before async readback completes, an all-current-view absence certificate may be structurally unavailable without a separate historical snapshot and retirement protocol. Never infer safe GPU reclamation from this state.
