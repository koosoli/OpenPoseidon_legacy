# Cached-view COUNT binding, 28 September 2026

The private per-view COUNT readbacks originally described one freshly drawn request. A cached shadow or sky image can be reused after that request is gone, so treating a later raw zero as an answer for the current image would be unsafe. The opt-in implementation now retains a mapped result only with its committed publication generation and target image identity for interior sky directions 0–4, GI RSM view 5 and local shadow tile 0. It keeps the original token/model/source revision/instance epoch. The local key also carries the atlas shape, allocation generation, light key and day/night cull index. The GI key carries its own RSM texture allocation generation and exact sky view. A missing draw, failed submit, abort, refresh, changed source/key/view/epoch or late readback returns Unknown.

The existing three-slot batch supplies raw COUNT words for interior directions 1–4. Binding requires the copied-word mask and that direction's successful CPU image publication in the same request. The ordinary renderer path still allocates no COUNT staging buffers, issues no new GPU copies and makes no Fine-release decision. The integrated Rust library check, focused state/publication/headless-GPU tests, combined desktop build and paired installed WGPU startup passed at b717811f. These checks establish the integrated path compiles and starts; they do not establish cached all-view visibility or matched performance.

Follow-up `2e8feec7` extends that historical publication binding to local shadow tiles 1–23. Each tile requires its copied batch word and exact successful same-request CPU publication, atlas allocation generation and shape, tile key, day/night cull index, instance epoch and source identity. Refresh, abort, stale source and late mapping fail closed. Four focused state tests and the strict actual-GPU tile 1/tile 23 test passed in the isolated port. The full Rust library suite reported 509 passes and four failures in other ABI/shader/grass tests; their baseline status is unverified. The integrated desktop build and installed runtime check are pending while Oliver uses the installed W12d game.

Follow-up `f425a651` exposes a private v2 diagnostic getter that harvests the existing 36 COUNT producers under one renderer borrow. It requires the exact current request's committed final-queue completion before classifying any view. Older facts are accepted only through their validated published interior/GI/local image bindings, with matching model, source revision and instance epoch. Its `required` mask is deliberately all 36 bits; inactive or skipped views therefore stay Unknown, and `status=1` requires every lane known. Twelve focused view-fact tests and the FFI layout test passed on the isolated branch. The integrated build and installed check are pending during Oliver's W12d game session.

Follow-up `472756be` freezes a per-request applicability mask before resource/draw gates from the configured solar/local counts, enabled interior-sky intent, current GI RSM eligibility and planar-reflection policy. Enabled-but-skipped views remain Unknown; inactive lanes are excluded. The plan must match the exact token/model/source/epoch and committed queue completion. Fourteen focused Rust view-fact tests, the local cached-count tests, FFI layout test, combined desktop build and paired installed WGPU startup passed on the integrated source. This is a diagnostic input observation, not a release certificate: cached interior/GI images can legitimately be older than the current instance epoch, and queue completion does not prove pixels or physical memory reclamation. No production policy consumer uses the snapshot. GeometryPage remains off and Fine retirement is forbidden.

Follow-up `59345e40` corrects two private diagnostic fields. `pending_samples` now counts committed, non-aborted COUNT copies still awaiting a map for the exact current request and applicable Unknown views; `dropped_samples` uses `UINT32_MAX` to disclose that the existing rings have no reliable drop counter. This getter-only observation adds no GPU work or policy decision. Fifteen focused Rust tests and the paired desktop build passed. The first installed startup attempt failed during renderer creation because its inherited stderr pipe closed; a retry with separate output files passed WGPU initialization and normal `--check` exit. No Fine release, matched FPS/no-regression or default promotion follows.

Follow-up `b02ee192` introduces an explicitly armed, optional retained-static target-model revision witness. Add, old/new-model update, remove, reused slot and both actual model-retirement paths advance its nonwrapping serial; unrelated-model changes and rejected stale handles do not. It is unconsumed by the COUNT/cache snapshot and does not weaken the global epoch check. Dynamic instances, section/mesh/material edits and pose changes remain outside this witness; they must be audited before using it to retain cached Absent facts. Two new focused mutation/overflow tests, the existing retirement test, `cargo check`, paired desktop build and installed WGPU `--check` passed. No default GPU work, Fine release or performance acceptance follows.

Follow-up `f80ad349` extends that optional witness to dynamic instances of the selected model. It compares their exact ordered GPU rows only while armed; target add/remove/transform/reorder advances the serial, while foreign-model changes do not. The normal path performs no extra scan or allocation. A device-free transition test, prior revision tests, Rust compile, paired desktop build and installed WGPU `--check` passed. Crucially, the old global epoch does not advance for dynamic-tail changes, so a cached COUNT fact must eventually bind this target revision or remain Unknown. The witness is still unconsumed. Mesh vertex uploads, resolved section/material changes, textures and pose palettes also remain untracked, and COUNT counts cull survivors rather than visible pixels. Fine release, physical reclaim, matched performance and GeometryPage default use remain forbidden.
