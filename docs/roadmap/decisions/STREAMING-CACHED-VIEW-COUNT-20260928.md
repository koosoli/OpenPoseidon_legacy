# Cached-view COUNT binding, 28 September 2026

The private per-view COUNT readbacks originally described one freshly drawn request. A cached shadow or sky image can be reused after that request is gone, so treating a later raw zero as an answer for the current image would be unsafe. The opt-in implementation now retains a mapped result only with its committed publication generation and target image identity for interior sky directions 0–4, GI RSM view 5 and local shadow tile 0. It keeps the original token/model/source revision/instance epoch. The local key also carries the atlas shape, allocation generation, light key and day/night cull index. The GI key carries its own RSM texture allocation generation and exact sky view. A missing draw, failed submit, abort, refresh, changed source/key/view/epoch or late readback returns Unknown.

The existing three-slot batch supplies raw COUNT words for interior directions 1–4. Binding requires the copied-word mask and that direction's successful CPU image publication in the same request. The ordinary renderer path still allocates no COUNT staging buffers, issues no new GPU copies and makes no Fine-release decision. The integrated Rust library check and focused state/publication/headless-GPU tests passed. Combined desktop build and installed startup remain pending at this checkpoint.

Local shadow tiles 1–23 still need the same historical publication binding. A callback for the main queue proves preceding queue work only; it does not prove each cached image's pixel visibility or physical memory reclamation. The existing 36-view state machine is not yet connected to an atomic, generation-aware snapshot. The experimental GeometryPage default remains off and Fine retirement is forbidden.
