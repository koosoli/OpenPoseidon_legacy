# TW-WATER-02 — W2: Tidewater Native open sea

Work order: *OpenPoseidon × Tidewater — Water Plan v5*, package W2.
Branch: `dec/tidewater-w2-open-sea`, on top of `dec/tidewater-w1-backend`.

## What is ported

These were ported source-faithfully from `dgreenheck/tidewater` @ `4811ba48` (MIT). They are
credited file by file in `CREDITS.md` → *Ported code*.

- **`OceanFFT.js` → `water_tw/fft.rs`.**
  - Four cascades at 733 / 157 / 33.3 / 7.1 m, 256², rgba16f.
  - Horvath/JONSWAP + TMA spectrum from two systems: local wind-sea and distant swell.
  - Two fused dispatches per frame: evolve + row IFFT, then column IFFT + sign + Jacobian foam.
  - A compute mip chain.
  - The only structural change: kernel B, not kernel A, writes mip level 5, so neither kernel
    binds more than four storage textures (OP runs with the WebGPU default limit).
- **`CDLOD.js` → `water_tw/cdlod.rs`.**
  - gridSize 32, leafSize 8, 12 levels, range factor 2.5, morph start 0.66, up to 1500 nodes.
  - Front-to-back order.
  - Selection runs in camera-relative space, because OP's view matrix has no translation.
- **`SeaDetail.js`** (gusts, slicks, windrows): the CPU noise texture uses the same seeds and
  fbm as Tidewater, plus `mulberry32`.
- **`FoamTexture.js`**: the 1024² foam lace is GPU-baked once when the backend is created.
- **`WaterSurface.js` + `WaterMaterial.js` → `water_tw/tw_water.wgsl`.** This is the
  terrain-only material variant:
  - exact dielectric Fresnel;
  - GGX sun glint with Cox–Munk unresolved roughness;
  - SSR against the opaque depth copy;
  - sky panorama reflection, with horizon occlusion;
  - Snell-traced refraction to the seabed through OP's heightmap;
  - Beer–Lambert absorption with single-scatter sun and ambient, multiple-scatter backscatter;
  - crest subsurface;
  - foam shading;
  - the Snell window and total internal reflection when seen from below.

## Adaptations to OP (all listed in the file headers)

- **Panorama.** OP's sky/cloud environment bake (`sky_env`) is the panorama the SSR falls back
  to. No new cloud renderer.
- **Sun and sky.** OP's CSM, terrain sun shadow and cloud sun shadow provide sun visibility.
  Unit mapping:
  - sunColor = π × `sun_diffuse` (OP stores E/π);
  - skyIrradiance = `sun_ambient`;
  - horizon = fog colour.
- **Wind.** Speed and heading come from `fft_wind_sea`, the same latched weather wind Current OP
  uses.
- **Fog.** OP's aerial perspective (`apply_fog`) is applied to the lit surface.
- **Refraction source.** Without RefractionPass (W4), refraction samples the opaque scene copy.
  This is Tidewater's own "not found" fallback.
- **Depth.** OP's water pass attaches depth read-only. Tidewater writes water depth; here the
  front-to-back node order keeps most of the overdraw benefit.
- **Planar reflection.** It does not run in this mode (`SurfaceProduct.uses_planar_reflection =
  false`), and neither does any Current OP water compute. The GPU timer list shows this:
  - new rows 78 "Tidewater: spectrum" and 79 "Tidewater: FFT + mips";
  - Current OP's FFT / foam / interaction / planar / underwater rows read n/a in Tidewater mode.

## Water tab

- The **Water backend** combo now enables "Tidewater Native".
- Tidewater mode shows its own group, and every control there has a consumer:
  - amplitude, choppiness, swell energy and heading, cascade scale;
  - foam coverage and intensity;
  - SSR and reflection strength;
  - roughness, crest subsurface, backscatter;
  - gusts, slicks, windrows;
  - debug view.
- These parts are listed greyed out as not ported: shore / breakers / wet sand (W3), spray and
  refraction pass (W4), underwater and caustics (W5), wakes (W6), and inland bodies (owner
  decision, see TW-WATER-01).
