# Cascade-0 target-model COUNT diagnostic

The private original-source GeometryPage probe (`WGR_GEOMETRY_MAIN_COUNT_PROBE=1`) now samples the selected renderer model in cascade 0 as well as the main view. The cascade has its own counter and asynchronous staging ring. Its result uses the existing 48-byte version-1 result layout through `wgr_shadow0_target_count_fact`; it does not reuse the main count.

A cascade result can become Present or Absent only after that cascade's real cull dispatch, an indirect depth draw in a closed render pass, the final encoder's queue submission, a successful render call, and a completed nonblocking map. At night, view index 0 can belong to a local-light atlas tile when there are no sun cascades; that tile is excluded. The request token, renderer model, source generation, and retained-scene cull epoch must still match. Missing cascade, missing draw, failed frame, stale epoch, saturated ring, or mapping failure leave the answer Unknown. The owner rechecks the original-source fixture and producer/model/instance association before logging it. The diagnostic does not consume an answer to release Fine geometry.

With the option off there is no staging allocation, copy, map, or GPU command. The normal renderer path continues to use the existing frame work. This is one view-level COUNT fact; it is not a pixel visibility result, all-view absence certificate, cache-coherence proof, or permission to evict geometry. A headless GPU test exercised an exact selected model with eight survivors and then an absent selected model with zero survivors in both the main and cascade-0 counter buffers. The integrating branch passed all five desktop targets, the focused GPU and FFI tests, and installed WGPU startup on `98923801` with Tidewater Native as the default. One installed original-source fixture, `build/stream-residency/cascade0-count-integrated-20260928-080859-766c49`, passed with exit 0, normal shutdown and no forced stop; current owner-bound main and cascade-0 facts both reported Present count 1 for tokens 3, 6 and 7. This proves the positive opt-in path on original-source fixture data, not a real-game zero, complete view coverage, physical reclaim, or matched FPS/no-regression.
