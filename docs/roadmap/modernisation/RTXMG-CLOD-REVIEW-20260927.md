## Verified transfer opportunities and limits

The [sample README](https://github.com/nvpro-samples/vk_lod_clusters/blob/1febfa7694ebdc8f97005a07897029272ca9e85a/README.md) describes mesh-shader rasterization, cluster-AS ray tracing, shared traversal, and RAM→VRAM group streaming. CPU clustering/simplification is reusable research; Vulkan mesh shaders, device addresses and CLAS operations are not WGPU indexed-draw APIs. Its cache has limited compatibility checking and processing can consume substantial time/memory. The attachment's “already solved” language is stronger than this evidence warrants.

The [generation explanation](https://github.com/nvpro-samples/vk_lod_clusters/blob/1febfa7694ebdc8f97005a07897029272ca9e85a/docs/lod_generation.md) explains locking shared group borders and regrouping them. This helps watertight transitions but does not automatically preserve P3D material sections, UV discontinuities, doors, openings or authored semantics. Upstream [clusterlod.h](https://github.com/zeux/meshoptimizer/blob/9e1f07b159d3cb777f1c67ed31fc11fd117986f4/demo/clusterlod.h) supplies attribute weights/protection and vertex locks. These require an explicit adapter. Its projection estimate is approximate; per-cluster `bounds.error` is explicitly nonmonotonic. Selection uses **paired group simplified-error predicates**, not an arbitrary parent/child threshold. Our whole-coarse/fine frontier concept cannot be substituted for this DAG cut without a coverage proof.

The [streaming description](https://github.com/nvpro-samples/vk_lod_clusters/blob/1febfa7694ebdc8f97005a07897029272ca9e85a/docs/streaming.md) excludes persistent coarse groups from configured memory limits, automatically expands their table capacity, and calls the strategies/basic defaults untuned. OpenPoseidon must charge roots, hierarchy, compressed CPU backing, decode/upload scratch, in-flight copies and delayed retirement within its own explicit budgets. A borrowed “85%” policy is no proof of total-memory safety or non-regression.

## Fit to the current renderer

`engine/WgpuRenderer/rust/src/gfx3d/cull.rs` currently represents instance→model→authored LOD→section, with Hi-Z inputs and indirect compaction. `gfx3d/mod.rs` implements indexed indirect submission and separate `prepare_shadows`, main preparation, skin baking and local-shadow paths. `EngineWgpu.cpp::RegisterGpuModel` builds meshes/sections and material bindings. These are useful foundations, not an existing cluster-page runtime.

A resident-only CPU CLOD bake can emit ordinary vertex/index ranges grouped by existing material/pipeline identity. That is technically feasible without mesh shaders. It still needs a new hierarchy consumer and bounded draw-list generation: one draw per small cluster can increase submissions dramatically. Material heterogeneity cannot silently become the sample's per-triangle material scheme. Every consuming pass must either use a compatible conservative cut or explicitly retain authored geometry: camera/depth/Hi-Z, sun and local shadows, sky visibility, direct/fallback paths, picking and auxiliary views. Gameplay Geometry/Fire/View/Roadway/Memory/Paths LODs remain authored and independent.

## Recommended bounded next experiment

1. Resolve notices and pin a minimal meshoptimizer CPU dependency; prefer upstream example first, evaluate the sample fork only if inner parallelism is needed. No RTX SDK import.
2. Bake **one original, static opaque, single-material visual shell/rock**, retaining all authored fallback/query LODs. Refuse deformation, proxies with changing visibility, transparent/cutout foliage and unknown material/selection semantics initially. Preserve original vertex attributes; disable lossy position/UV quantization initially.
3. Set explicit input/output/peak-scratch and hierarchy limits before allocation. Validate finite coordinates, indices, overflow and monotonic group-error requirements. Upstream output callback returns a group ID; it is not a verified cancellation API. Its `std::vector` scratch is outside meshoptimizer's allocator hook, so that hook alone cannot enforce the full budget. Prove cancellation/error unwinding between bounded jobs before considering live preparation, with no nested unbounded worker pool or owner-thread bake.
4. Produce a versioned cache keyed to immutable source evidence, adapter/material partition rules, exact library revision and settings. Temporary publication plus checksum/length checks; stale, corrupt or unsupported data falls back to authored geometry. Do not inherit the sample's weak cache invalidation.
5. Prove resident-only coverage at mixed-distance cuts, shared boundaries and material seams, plus all required passes. Compare exact same camera/quality on supported adapters and original assets: frame tails, draw count, triangles, bake cost, CPU retained bytes and GPU pool ranges. Only then consider asynchronous page requests with resident coarse fallback and cancellation tokens. Queue overflow/missing children must retain a complete valid cut, never holes or overlapping duplicate surfaces.

Recommendation: refine Stage G's research reference toward meshoptimizer + the Apache sample, while retaining the roadmap's gated experiment. Do not replace the current streamer, claim Nanite parity, or promote this to a default implementation on source evidence alone.
